# VEDIC — The Language of GlobalGrid2050
## Owner-directed development scope and operating charter
26 November 2026 | Lead: Tacit 1 | Coordination: Neural Link #87

### 1. Mission
Make existing software intelligence understandable and reusable by humans and AI. Translate what code achieves, rather than merely describing syntax. The owner has authorised a continuously expandable dictionary: functions, meaningful bodies, packages, workflows, application capabilities and validated compositions can all become entries. New combinations may themselves become building blocks for future combinations. Do not claim arbitrary combinations are meaningful or executable. The initial dashboard is a preview, not a completed translation of the producer-reported 477,785 unique numbered lines (Modular Star snapshot 25 Nov 22:43 UTC).

### 2. Respect existing architecture and previous agents
- Modular Star remains the authoritative permanent numbered line, tablet, element and family inventory. Do not renumber, rescan the estate unnecessarily or change its existing hourly workflow. Use release assets modular.sqlite.gz and catalog.json.gz; mutable release tag is not an immutable pin. Reuse unpack(), rebuildTablet(), elementSource(), find-prior.mjs and existing permanent-number checks. Python adapters are read-only and require parity evidence.
- Periodic Table is the existing functional block catalogue; retain its permanent numbers, symbols and categories (e.g. Vg, Vn, Gc are distinct until evidence supports identity). Do not infer exact membership from matching names.
- Spider Genome supplies source-backed dependencies and lineage. Maths Genome supplies canonical mathematical relationships and documented duplicate/drift/should-import distinctions. Do not convert should-import into actual calls.
- Existing Vedic classification has Structure, Movement, Computation, Flow and Data; use those classes as one axis, not a replacement taxonomy. Existing Chemistry graph provides composition compatibility evidence, where applicable.
- Kuiper Belt is the estate navigation and evidence framework: a body should have an openable destination; a claim without a reproducible key is a candidate. Keep application/repository depth distinct from function depth. Do not duplicate its renderer, taxonomy or orbit calculations.
- CVAA preserves lessons as executable safeguards. Reuse existing vaccines and pin their registry when applicable. VEDIC local tests are not installed CVAA vaccines. Do not change upstream registry without separate scope.
- Spider Printer: locate and reuse the existing implementation and its contract before claiming integration. Local browser printing is an interim action, not Spider Printer.
- Pipeline News / REPD and SatNav supply existing SCADA style and interaction patterns. Leave all producer applications and GlobalGrid2050 homepage untouched.

### 3. Permanent dictionary identity
Follow the REPD identity stability precedent GG2050-REPD-<Ref ID>, with a distinct VEDIC namespace GG2050-VEDIC-000001 onward. Numbers allocated once by Tacit 1's append-only registry; never recycle or reassign. Keep initial IDs 1–6. Preserve retired records with a tombstone/status, never silently delete. Version meaning/contracts, sources and demonstrations without replacing the stable identity. Substantively different capabilities or combinations receive new IDs. Equivalent aliases and multi-view representations point to the canonical entry; same source occurrence does not automatically prove semantic equivalence. VEDIC IDs do not substitute for existing Stars, REPD or Periodic Table identities. Validate stability against previous Git version; protect historical releases.

### 4. Language and data contract
Each entry should carry: gg_id; immutable registry key; shorthand word or phrase; plain-English purpose; kind (function/body/package/workflow/application/composition); inputs and outputs with types, units and bounds; triggering condition; limitations; dependency/component references and version pins; source repository/commit/path/blob/physical ranges and columns where available; original Stars line/element/family IDs when resolved; application/estate contexts; Periodic Table category and block; Vedic class; computer-science and maths discipline tags; evidence state; demonstration descriptor; proof receipts and date; supersession/retirement information; credits. Unknown remains null, never zero or pass. Current schema is a deliberately narrow six-entry seed; evolve additively, document migration, do not imply all these fields already exist. Separate curated candidate classification from exact producer membership. Distinguish manifest-declared, static source inference, historical, executed tested assertion, live verified and unknown; use separate axes where necessary. Source-reviewed text is not an executable language by itself.

### 5. Recursive composition / grammar
A composition is an ordered or explicitly parallel dependency graph of existing stable entries, with typed input/output ports, units, parameters, constraints, error behavior and source/test receipts. A successful composition can become a new dictionary word and be nested in later compositions. Detect cycles, missing dependencies, incompatible types/units, unsupported side effects, duplicate aliases and missing data. Preserve explicit order when relevant; distinguish a set of functions from an executable pipeline. Do not silently convert coordinate order, voltage units, power/energy, or distances. Require reproducible demo and appropriate tests before promoting executable status. Reuse existing code generator and Chemistry evidence before creating a new engine. The first ORIENT candidate combines existing MEASURE and BEARING functions on shared inputs; it is not turn-by-turn navigation or engineered routing. No claim of infinite valid combinations.

### 6. Demonstration law
Every entry must provide an openable demonstration link where feasible, or explicit reason why unavailable. Distinguish exact-source runnable demo; existing application example (not proof of exact function execution); historical example; static source/explanation; unavailable. A demonstration is not a proof of all real-world behavior. Use upstream implementation without rewriting maths, pin source and verify bytes, retain licence and NOTICE. Show example inputs, outputs, units and limits; accept safe editable inputs where appropriate. Avoid live private data, secrets, unapproved API calls or infrastructure access. Capture expected outputs and negative cases in Python-driven browser tests. A failed link is a measurable issue, not a silent success. Kuiper's openability principle applies to every entry.

### 7. Dashboard (reuse REPD pattern)
Black/cyan GlobalGrid2050 SCADA, consistent with Pipeline News and SatNav. Use one canonical dictionary register, not multiple competing tables. Primary columns: Word/short meaning, DEMO action immediately beside word, expandable plain-English meaning, estate group, discipline/function group, permanent GlobalGrid ref. Further fields expand or scroll sideways: kind, Vedic class, Periodic Table block, source, proof, inputs/outputs, combination and dates. Desktop sortable headers; mobile compact first column, touch-friendly controls, bounded horizontal table scroll, no page overflow, expandable details. Sort alphabetically A–Z/Z–A, by ID, estate/application group, Periodic Table category, discipline (computer science/maths/engineering/etc), and existing Vedic classes. Filter independently on same underlying rows; missing mappings remain searchable. Add pagination (100 rows per page when scale warrants), filtered export, clear filters, counts, and expanded/print view by reusing existing patterns. Avoid visual clutter, misleading aggregate counts and unrelated themes. Existing architecture dashboard remains reachable; dictionary and anatomy are views of shared data.

### 8. Python-first autonomous workflows
Use Python for snapshot acquisition, read-only SQLite joins, packed little-endian line IDs, distinct-ID set unions, deterministic catalogue generation, identity stability, schema and composition validation, provenance, link checks and browser CI. Reuse JS/Acorn, existing engines and Spider receiver where already functional. VEDIC consumer workflow is separate from original Stars producer; run every six hours after merging to default branch and on demand. Pin asset identity/digest and hashes, reject changing input during download, report actual census; retain compact run receipts. Raw producer database temporary, not published or modified. Future adapters must resolve exact repo+commit+path and blob, preserve columns, verify reconstruction parity, and leave unknown identity null. Use snapshot+tablet cache only after measurement; one shared adapter for views. Distinguish inventory counts from translated unique line union; never sum overlapping spans. Existing scripts and tests are durable in Git. Future agents must be able to recover from README/charter, exact heads, receipts and Neural Link without current chat. Deterministic workflows may run unattended; AI semantic translation requires actual invocation or approved model workflow, not a scheduled shell pretending to understand code.

### 9. Team and collaboration
Tacit 1: sole lead, language/registry/dashboard/demos/integration, Python consumer, releases. Tacit 2: source-backed translation batches, actual DB resolution research, independent Python/Chromium/WebKit/mobile verification; no duplicate dashboard/registry. Tacit 3: concise context recovery and scope control, read-only, conserve context; record decisions, exact heads, last ACK, proof and next owner, flag drift. Tacit 4: two-hour authorised advisory window only, identify duplicated identity, code, processing and effort; reuse recommendations, no competing implementation. Independent QA is intentional redundancy. Respect every past agent. ACK relevant new directives with 🖖, post exact head and evidence, credit contributors, report failures and unknowns. Neural Link is a polled mailbox, not an executor. Retain existing two bounded ChatGPT schedules only where technically needed; no extra slots.

### 10. Acceptance and publication
Owner authorises first useful VEDIC preview, ideally 04:29 UTC 26 Nov, before waking. Release priority is honest useful preview, not full-corpus completion. Gate exact-head Python unit/negative tests, pinned source hash/range checks, immutable identity regression, composition compatibility, browser tests Chromium and WebKit desktop/mobile portrait/landscape, dictionary sort/filter/search, all seeded demo links, invalid inputs and no page overflow; independent review; verify public served bytes after deployment. If Pages access or tests fail, state exact blocker and preserve prior release; never claim live from a commit alone. No upstream modifications or homepage promotion. Target https://ventusltd.github.io/vedic-/ if enabled. Current preview work stays in PR #1 until gates; no guarantee of deadline. Full-corpus coverage, exact Stars IDs, live handset acceptance and Spider Printer integration remain distinct outstanding milestones.
