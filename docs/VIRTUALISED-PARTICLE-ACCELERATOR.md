# VEDIC Virtualised Particle Accelerator

Use known operations as clues. Evaluate the clues across the pinned Modular Star index, then draw reproducible shots for source review. The accelerated pass keeps trial-by-element scores on the device and exports the strongest group and its evidence. NumPy verifies numerical classification independently of the CUDA kernel. Source review verifies what the operation does.

## Repeat the four passes

1. **Words.** Tokenise symbols, signatures, docstrings, dependencies and bounded element tokens. Weight explicit symbols above incidental body terms.
2. **Patterns.** Use seeded verb and object combinations. Retain a unique supported group or record review required. Preserve prior/current disagreements on identical element digests. Use a seeded golden-ratio rotation over permanent-ID order to spread review shots.
3. **Exact strings.** Search the full set of unique indexed lines for literal UTF-8 fragments. Keep original line IDs.
4. **Whole blocks.** For proof controls or sampled leads, reconstruct the physical span from its indexed lines and check its complete SHA-256 and all tablet placements. Check the source contract before suggesting promotion.

The implementation applies Trillion Loop's resident evaluation, independent arithmetic check and provenance gate. The distribution of review shots is inspired by Kuiper's use of [Vogel's golden angle](https://github.com/Ventusltd/kuiper-belt/blob/f7a4cb9e3a764a72b7133bb275bb5387ea083be2/editions/202610311905/workers/W14-kuiper-mathematics.md#L235-L248). The selected shots are for discovery and failure analysis.

## Measured evidence

The 512-crib pass scored 17,597,440 element-hypothesis pairs on the RTX 5070 Ti. It tracked 34,370 elements, 33,221 families and 478,800 unique lines. There were 6,171 single-group element leads across 31 populated groups and 28,199 element records marked for further review. The pass retained 2,514 disagreements relative to the earlier 384-crib recipe. Both the seed and the clue set changed between those recipes. CuPy took about 24 ms including transfers after warmup, compared with 88 ms for NumPy. Group, score and winning-clue selections agreed exactly.

Independent stratified shots found a new source-backed lead, **CALCULATE GROSS CONGESTION RENT**, and a candidate to **READ DECLARED MODULE DEPENDENCIES**. Further cases exposed incorrect groups, overlapping operations and duplicated historical placements. The independent samples establish specific source findings. They provide no estate-wide accuracy estimate. The 44-group library covers Energy Transition Simulator, the REPD pipeline, market data, GridAtlas, off-road SatNav, overhead and underground cable work, LiDAR terrain, SLD animation and the dated Financial Sandbox. The public application links in the library supply user-facing terms. The code scan uses repository, path and indexed line evidence. A route preview or a historical drawing remains scoped to its own generation.     python tools/estate_domain_scan.py modular.sqlite data/estate-crib-library.json domain-output --spider genome.json --seed 20261127

The line scan walks permanent IDs in order and applies each group to every batch. Source context comes from the repository and file placements. Direct clues use the line text. The two masks preserve independent evidence and multiple groups without assigning new IDs. Vogel review shots retain the input line ID. The optional genome input extracts file-and-line references from the existing Spiders graph. [Spiders genome](https://github.com/Ventusltd/spiders/blob/830e86ea65e98b03df7250d2dd55d2753799687a/species/genome-spider/data/genome.json)

The 44-group run tested 21,067,200 line-group pairs, with full NumPy and CuPy mask parity. It identified domain context or direct clues for 219,113 unique lines. The union with the element-group pass covered 254,211 of 478,800 indexed line IDs. There were 3,468 lines with direct lexical evidence and 597 with same-group lexical and path evidence. The domain scan produced a 796,590-byte Parquet and extracted 25 cross-repository references from the 1,379-node, 3,249-edge Spiders genome. The narrow, transfer-inclusive domain kernel took 191 ms on the GPU and 175 ms with NumPy. Preparation took about 3.3 s.
