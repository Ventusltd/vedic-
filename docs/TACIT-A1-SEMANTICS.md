Output plan schema vedic.compound-plan.v1: instruction, inputs, state, steps, comparison, reason, manifest_sha256, plan_sha256. Step fields id, operation, meaning_id, keys, inputs, from_point, to_point, depends_on, outputs. Digest uses factory canonical ASCII sorted compact JSON + LF, excluding plan_sha256. Host recomputes whole plan with Resolver.verify; self-hash is not authorization. PLAN_PROPOSED only ORIENT steps, PARTIAL_PLAN means execute only admitted listed steps with explicit comparison refusal, ABSTAIN zero steps. Comparison is {operation:"nearer_destination",depends_on:["s1","s2"],state:"REFUSED_NOT_ADMITTED",quantity:"distance_km",unit:"km"}; no ranking performed. Both ORIENT steps independent, comparison depends on both. No comparison approval inferred from RANK or CHOOSE; those have different typed inputs/admission. Coordinates use original named degrees, spherical model radius 6378.137 km, no route/capacity inference.
Grammar: complete positive parse of bounded ORIENT or distance-and-bearing clauses; arbitrary labels A–Z with 2–9 named points, up to 8 pairs; shared origin shorthand after first pair. Unknown terms, disjunction, negation, contradictory origins for comparison, duplicate references, unsupported units/CRS, unknown point names, undefined headings refuse. This is not unrestricted natural language comprehension. Nearest 132 kV request explicitly research/unadmitted. No external geocoding or data assumptions.
