# REPD-style VEDIC command discovery and reuse
The browser fetches a global compact search index and only detail pages required for the current 100 results and their declared composition components, in batches of four requests. Generated pages are CI Pages output, not committed files. The canonical append-only registry and historic releases remain intact. A filtered result page may reference multiple detail shards; only selected records are retained. The global index itself grows, so measure mobile memory at larger scale.
Search spans every command, alias, symbol, meaning, discipline, class, and pattern, plus known family references. Broad lexical labels are discovery hints, not proof of equivalent functions. Independently reviewed pattern_tags and aliases may refine them. A similar-function filter helps developers locate previous work before writing new code. No continuous prose is fetched by the current interface.
Use Seed governance, Kuiper permanent source identities, Modular Star family IDs, and Faraday numbered experiment evidence. A future typed execution pulse may combine admitted package dependencies into one verified command; a search match is not execution permission. Keep raw occurrences, provenance, and family-level candidate records in compressed producer assets / bounded Parquet artifacts rather than adding code to Git.
## Daily compressed discovery and reviewed admission
Keep the existing 03:37 UTC workflow and one bounded daily source function discovery. Additionally read the producer's verified compressed catalogue (rather than its full SQLite snapshot), advance 100 existing Modular Star family IDs per successful cycle, derive lexical plain-English pattern groups and candidate names, and store ZSTD Parquet in short-lived Actions artifacts. No code copied into Git. The current queue is deliberately empty: lexical similarity is not a reviewed command. Each reviewed queue record contains decision REVIEWED_FOR_ADMISSION, family_refs (real producer IDs for the canonical function, not all shared dependencies), and entry (the existing source-only dictionary schema with pinned source and review receipt, creation evidence, purpose, inputs, output, limits, application, optional aliases/pattern_tags; no permanent number or gg_id). T3 owns this append-only review queue. The daily script rejects existing words, symbols, aliases, senses and mapped root families, allocates at most 20 new permanent IDs, and prepares an append PR only if new approved rows exist. The historical 69-row allocation replays independently; future suffix rows must replay from the daily review queue. Existing PR blocks another automatic daily PR. The scheduled job does not merge or deploy directly. GitHub token permissions may prevent PR creation or dispatch; retain evidence rather than bypassing repository policy. The rolling cursor is best effort (14-day artifacts), wraps after the inventory and replays safely. Coverage is bounded to the producer catalogue and cannot claim semantic or runtime completeness. A family pulse is indexing and selection, not an executable Faraday package. Connect actual execution only through the admitted package factory, immutable dependency closure, permission and independent results.
