# REPD-style VEDIC command discovery and reuse
The browser fetches a global compact search index and only detail pages required for the current 100 results and their declared composition components, in batches of four requests. Generated pages are CI Pages output, not committed files. The canonical append-only registry and historic releases remain intact. A filtered result page may reference multiple detail shards; only selected records are retained. The global index itself grows, so measure mobile memory at larger scale.
Search spans every command, alias, symbol, meaning, discipline, class, and pattern, plus known family references. Broad lexical labels are discovery hints, not proof of equivalent functions. Independently reviewed pattern_tags and aliases may refine them. A similar-function filter helps developers locate previous work before writing new code. No continuous prose is fetched by the current interface.
Use Seed governance, Kuiper permanent source identities, Modular Star family IDs, and Faraday numbered experiment evidence. A future typed execution pulse may combine admitted package dependencies into one verified command; a search match is not execution permission. Keep raw occurrences, provenance, and family-level candidate records in compressed producer assets / bounded Parquet artifacts rather than adding code to Git.
## Daily compressed discovery and reviewed admission
The 03:37 UTC schedule scans up to 100 catalogue families and admits up to 20 reviewed commands per successful daily run. Keep these original caps until measured on CI. The compressed source catalogue is digest-verified; candidate names and patterns remain non-executable discovery hints. ZSTD Parquet receipts are retained as before, but cursor persistence does not depend on their retention.

A separate non-public-interface state branch, `automation/vedic-research-state`, stores `state/family-research.json` with cursor, pass number, completion flag and producer identity. First creation is explicitly logged; subsequent malformed or inaccessible state fails closed. The state advances only after a successful snapshot artifact is downloaded, with a fast-forward-only push and expected branch-head check. PR rehearsals never write state. A producer catalogue can change during a pass; new lower IDs may be discovered in the next pass, so the counter is not a claim of exhaustive semantic coverage.

Pending queue rows are explicitly reviewed records (decision REVIEWED_FOR_ADMISSION, positive real family_refs, existing source-only entry schema). Invalid or conflicting individual records are held with indexed diagnostics, not given permanent IDs. A family may be shared only with an explicit reviewed family_overlap_reason; distinct canonical names, aliases, symbols and sense keys are still required. Candidate evidence is validated before allocation. Network failures may stop the workflow rather than silently trust unavailable evidence.

Only admitted records are removed from the pending queue, and they are appended chronologically to data/admitted-queue-archive.json in the same admission PR as the dictionary. Unprocessed or held records remain pending, including items beyond the cap. Prior reviewed records are never revalidated against changing producer family membership. Exact ordered archive replay reconstructs the dictionary suffix from the frozen 69-command baseline, and the proposal is replayed and partition-checked before commit. T3 retains review and publication authority. No automatic merges, arbitrary execution or source copying. Repository permissions or unavailable source evidence may still block admission; do not bypass repository rules.
