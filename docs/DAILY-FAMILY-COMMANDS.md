# Daily family command pulse

The scheduled run at 03:37 UTC consumes the verified existing Stars compressed catalogue, not the full code database. It scans 100 numbered families per day, stores only a ZSTD-compressed Parquet pulse and compact receipt in 14-day Actions artifacts, and advances from the latest successful receipt. It wraps on reaching the end. The producer remains the source of truth, no source copied into VEDIC. Review or alias collisions are held, not silently merged. The published dictionary is deliberately compact, with permanent append-only IDs; the UI defaults to A–Z.

MSI integration supplies reviewed entries in data/daily-command-queue.json: records contain decision REVIEWED_FOR_ADMISSION, family_refs (existing integer Stars IDs), and entry (the existing source-only dictionary record shape without number or gg_id). Preserve existing pinned source, purpose, limits, review receipt, creation evidence and application. Up to 20 reviewed additions per day. No semantic claims are made from a function name alone. All queue data must be reviewed; no credentials, raw code, or unlicensed material. Family links here are review assertions, not verified execution or permanent identity equivalence. The actual queue is initially empty.

The workflow proposes a PR if there are new approved rows and dispatches existing anatomy CI explicitly because GITHUB_TOKEN events normally do not trigger workflows. A maintainer must merge through repository rules. No duplicate row and no commit if no new reviewed entries. PR creation may be disabled in repository Actions settings; report the error and retain artifact. No auto-merge or direct production push.

Seed governance: https://github.com/Ventusltd/seed-data. Faraday records: https://github.com/Ventusltd/faraday. The existing Faraday repository is a numbered experiment log, not a generic runtime engine. A computational pulse is an intended future typed command-to-family/package closure: input contract, selected family and dependency graph, versioned package/entry point, permissions, deterministic output and independent test receipt. Do not execute arbitrary discovered code. Preserve failures, uncertainty and original evidence. Dependency name matches alone are not proven closure. The daily Parquet pulse is an indexing/selection artifact, not an execution proof. Future MSI work must connect existing factory and admitted package registry rather than invent a new engine.

This first pass covers the producer's published family inventory, not the complete historical estate, non-indexed languages or excluded files. A rolling cursor is best-effort across expired artifacts or changed producer snapshots; replay is safe and no permanent entry is duplicated. Full coverage and semantic review require sustained work.
